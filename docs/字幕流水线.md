# 泰语字幕流水线（离线 ASR）

把课程音视频变成播放器可直接加载的中泰双语字幕。

```bash
# 最省事：用 .env 里已有的 Azure 语音密钥（--engine 默认 auto 会自动选中）
python3 scripts/thai_asr_subtitles.py 课程音频.mp4 --id lesson-01

# 只识别不写文件（先探一遍断句和字数）
python3 scripts/thai_asr_subtitles.py 课程音频.mp4 --id lesson-01 --dry-run

# 自建引擎（见下文「引擎」）
python3 scripts/thai_asr_subtitles.py ep1.wav --id ep1 --engine qwen3
python3 scripts/thai_asr_subtitles.py ep1.wav --id ep1 --engine openai --asr-base-url http://127.0.0.1:8080/v1

# 顺便量一版泰语识别 CER（有可信参考文本时）
python3 scripts/thai_asr_subtitles.py ep1.wav --reference ep1.script.th.txt

# 离线自测（不消耗任何额度）
python3 scripts/test_thai_asr_subtitles.py
```

依赖：`ffmpeg` / `ffprobe`（必需），Python 3.9+ 且**只用标准库**。
Qwen3 引擎额外需要 `pip install -U qwen-asr`（+ torch / GPU）。

## 产物与对接方式

默认写到 `backend/subtitles/`（该目录在 `.gitignore` 里，属于运行时资源，随服务器部署而不是随 git 发布）：

| 文件 | 用途 |
|---|---|
| `<id>.th.vtt` | 泰语字幕 → 课程数据 `subtitleUrlTh` |
| `<id>.zh.vtt` | 中文字幕 → 课程数据 `subtitleUrl` |
| `<id>.th.srt` | 泰语 SRT，交给 `subtitle_refine.py` 或人工校对 |
| `<id>.bilingual.srt` | 中泰对照，**校对就看这个** |
| `<id>.report.json` | 本次运行报告：分段数、字数、覆盖率、CER、警告、翻译详情 |

后端 `backend/app.js` 已把 `/subtitles` 静态映射到 `backend/subtitles/`，
播放器 `src/pages/LessonVideo.jsx` 用 `<track srcLang="th" ...>` / `<track srcLang="zh" ...>` 两条轨，
所以课程数据里填：

```js
subtitleUrlTh: "/subtitles/lesson-01.th.vtt",  // 泰语
subtitleUrl:   "/subtitles/lesson-01.zh.vtt",  // 中文
```

运行结束后脚本会把这两行直接打印出来，复制即可。

## 引擎

| 引擎 | 参数 | 说明 |
|---|---|---|
| `azure` | `--speech-key/--speech-region`（默认读 `SPEECH_KEY` / `SPEECH_REGION`） | 用现有 Azure 语音密钥，泰语可用、无需 GPU、无模型下载；按音频时长计费 |
| `qwen3` | `--qwen-model` / `--qwen-device` / `--qwen-vllm` | 自建 [Qwen3-ASR-1.7B](https://huggingface.co/Qwen/Qwen3-ASR-1.7B)（Apache-2.0，官方支持泰语），需要 GPU；CPU 也能跑但慢 |
| `openai` | `--asr-base-url/--asr-api-key/--asr-model`（默认读 `TRANSCRIBE_API_URL`） | 任何 OpenAI 兼容的 `/audio/transcriptions`：whisper.cpp server、faster-whisper、自建网关 |
| `mock` | — | 离线假数据，只用于自测和 CI |

`--engine auto`（默认）：有 Azure 密钥就用 azure，其次看 `--asr-base-url`，最后退回 mock。

### 为什么时间轴是「静音切分 + 按字数分配」而不是词级时间戳

这是本次落地时逐条实测过的结论，换引擎前先看这一节：

1. **Azure fast transcription 在 eastasia 不可用**（`speechtotext/transcriptions:transcribe` 返回
   `Fast transcription is not supported in this region.`）。
2. **Azure 短音频 REST 可用但不返回词级时间戳**：`format=detailed` 里只有 `Offset` / `Duration`
   （整段级别）和 `NBest.ITN`（带分词的文本）。
3. **Qwen3 的词级时间戳依赖 ForcedAligner，而 ForcedAligner 的 11 种语言不含泰语**
   （zh/en/yue/fr/de/it/ja/ko/pt/ru/es），所以泰语也拿不到词级对齐。

于是统一做法：用 `ffmpeg silencedetect` 把音频切成语音段 → 逐段识别 → 段边界 +
引擎返回的 offset/duration 作为 cue 时间 → 长句再按**泰语空格/标点**断句、按字数比例分配时间。
因此：

- 停顿清楚的材料（课程朗读、情景对话）时间轴很准；
- 一口气连续朗读超过 `--max-segment`（默认 10s）时，会被均分成小块，块内时间轴是估算的——
  报告里会明确写这条警告；
- 想要更细的时间轴：调小 `--max-segment`（例如 6），代价是请求变多。

## 泰语特有的两个坑（脚本已处理）

1. **`subtitle_refine.py` 会删掉所有空白**（它的 `_normalized_text` 是 `re.sub(r"\s+", "", ...)`），
   泰语词间空格会被一起吃光。流水线复用它的归并逻辑后，用识别得到的词序把空格**贴回**，
   并有两道闸保证只动空格：贴完的紧凑文本必须逐字一致，且未匹配字符占比超过 30% 就整体放弃贴空格。
   这样即使词序漂移，也只会"没有空格"，不会"改字"。
2. **断句不能落在泰语组合符号前面**（声调符号 ่ ้ ๊ ๋、上/下加元音 ั ี ึ ุ ู ์ 等），
   否则会出现「基辅音在上一句、声调符号在下一句」的坏字幕。断句点会自动后移，
   宁可单条略超 `--max-len` 也不拆散音节。

## 实测数据（2026-09-24，本机 eastasia 密钥）

| 素材 | 时长 | 结果 |
|---|---|---|
| Apple `say -v Kanya` 合成课程脚本（**已知文本**，可信参考） | 161.5s | 34 段 → 31 条；CER **22.4%**；语音覆盖 96.8% |
| `subtitles/ep1_audio.wav`（真实课程音频） | 256.1s | 34 段 → 40 条，768 字，均 19.2 字/条；语音覆盖 46.7%；中译 40/40 成功 |

CER 的误差构成（人工核对）：泰语**字母名称**（`ก.ไก่` → `กอไก่`、`ฮ.นกฮูก` → `ฮ่อนกฮูก`）、
**声调符号**（`วิ่ง` → `วิง`、`ช่อ` → `ชอ`）、以及参考文本自身笔误（脚本里写的 `alloween`，
音频其实是另一个词）。结论：

> ASR 产物是**可校对草稿**，不是可直接上线成品。课程字幕建议对照 `<id>.bilingual.srt` 人工过一遍，
> 尤其是字母名称和声调；新闻/影视这类需要成品的场景，人工校对环节不能省。

`report.json` 里的 `speech_ratio` 是快速体检指标：明显偏低（< 50%）说明不少时长没有字幕，
多半是停顿很长或存在漏句，先听一遍再决定是否调 `--noise-db` / `--min-silence`。

## 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--max-len` | 30 | 单条字幕最大字数（按去空白计），泰语教学字幕建议 25–30 |
| `--max-segment` | 10 | 单次请求最长音频秒数；调小 → 时间轴更准、请求更多 |
| `--noise-db` | -35 | 静音判定阈值；素材底噪大就调高（如 -30） |
| `--min-silence` | 0.45 | 判为停顿的最短静音；朗读停顿短就调小（如 0.3） |
| `--pad` | 0.12 | 语音段前后留白 |
| `--thai-text` | spaced | `spaced` 保留词间空格（学习友好）；`display` 用无空格的显示文本 |
| `--refine` | auto | `auto/on` 用 `subtitle_refine.py` 归并；`off` 用内置归并（该模块未入库，缺失时自动兜底） |
| `--no-translate` | — | 不生成中文轨；翻译出口默认走 `AI_BASE_URL/AI_API_KEY`，不可用时自动回落到 `DEEPSEEK_API_KEY` |
| `--keep-temp` | — | 保留切片 wav，便于排查某一段 |

密钥可用性校验与后端 `backend/aiProvider.js` 的 `isUsableKey()` 同口径：**中文占位符、长度异常、
含空白的值一律视为"没配"**，会打印明确原因并跳过（`AI_API_KEY` 目前就是中文占位符，
所以翻译实际是走 `DEEPSEEK_API_KEY`）。

## 许可（做数据闭环前必读）

| 模型 | 许可 | 能否用于改进自己的模型 |
|---|---|---|
| Qwen3-ASR（推荐自建） | Apache-2.0 | 可以 |
| Typhoon ASR（泰语专用，114M，可 CPU 跑） | CC-BY-4.0 | 可以（需署名） |
| Whisper | MIT | 可以 |
| netease-youdao/Confucius4-R2T2 | 网易自定义许可 | **不可以**（明确禁止用其输出改进其他 AI 模型，除非你的模型非商用；另有 MAU/营收门槛与中国大陆法管辖） |

也就是说：想用 ASR 输出反过来微调/蒸馏自己的模型，选 Qwen3-ASR 或 Typhoon ASR，别用 R2T2。

1. **流式听写**替换前端 `src/components/speaking/SpeakingRecorder.jsx` 里的浏览器 Web Speech
   （`lang="th-TH"`，只有 Chrome 有、音频出到 Google）：用 Typhoon ASR streaming 115M 在本机 CPU
   起服务，走 WebSocket/SSE，句末仍送 Azure 做音素评分（评测能力不受影响）。
2. **声调可视化**：ASR 给不了声调反馈，用参考音与学生录音各算一条 F0 曲线叠加对比，
   把 `ม้า / มา / หม่า` 这类错误可视化——这是 Azure 四维分也没有的维度。
3. **校对工作流**：把 `<id>.bilingual.srt` 的校对结果作为 `--reference` 回灌，量出人工修订率，
   评估泰语 ASR 是否值得进一步投入。
